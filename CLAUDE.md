# CLAUDE.md — Curve Archaeology operating rules

These rules govern every agent working in this repository, in every phase. They are binding; a hypothesis or result that violates them is void. See `PROPOSAL.md` §2 for the evidence standard and §3 for the operating-rules rationale.

1. **No constants from memory.** Every curve parameter, seed, S-box and test vector is fetched from a primary source and stored in `data/params/*.json` with source URL, document section, SHA-256 of the fetched file, and fetch date. Cross-check each value against a second independent source (OpenSSL explicit parameters, the std-curves database, PARI, or a library test vector). Where a standard publishes a fingerprint of its parameter file, reconstruct the file and match the fingerprint. A value that fails its cross-check blocks the phase. Parse constants from source files by script; never retype a multi-hundred-bit value.

2. **Hypothesis registry.** Every hypothesis is a row in `registry/hypotheses.yaml` *before* it is run: target, generator, slicing, transforms, parameter ranges, `search_bits`, capacity, controls. After the run: `match_bits`, `margin`, tier, commit hash, wall time. Rows are never deleted. Nothing is tested off the books — including quick checks in a notebook. Third-party results are imported with a status column (`claimed-negative-unverified` → `reproduced`/`refuted`) and a re-verification sample.

3. **Evidence standard (tiered; capacity first).** For a claim "procedure H produced target T": `match_bits` = bits of T reproduced at positions fixed before comparison; `search_bits` = log2 of all hypotheses the pipeline would have reported for T or any sibling, across all phases (a whole state space counts in full); `margin = match_bits − search_bits`. Tier A (explained) margin ≥ 64; Tier B (probable) 32–64 with one independent corroboration; Tier C (lead) 16–32, never called an explanation; below 16 is logged noise. Write each target's capacity (entropy) and best reachable tier before searching. For an explanation obtained by algebraic recovery rather than enumeration, report target bits minus recovered-seed bits plus the bit-exact forward reproduction. Report margin and tier with every claim.

4. **Generators are bit-exact.** Each generator in `gens/` ships with two independent test vectors (source-embedded or published output, and a reference runtime). An unverified generator invalidates every negative it touched. Re-implement `lrand48` and FreeLIP `zrandom` from their C sources, not from any published Python.

5. **Cross-target consistency.** A procedure claimed for one target is run on every sibling from the same standard and era. A one-target explanation is flagged weak and cannot exceed Tier B.

6. **Gates.** At each gate write `reports/phaseN.md` and stop. Do not start the next phase in a chain without user sign-off.

7. **No public disclosure.** Nothing is posted, emailed, or pushed to a public remote. Findings and gate reports go only to a private remote. The agent contacts no third party; the user does.

8. **Controls for every negative.** A negative is valid only if (a) planted targets (same generator and slicing, random seeds) are recovered by the same pipeline at ≥99% over ≥100 trials, and (b) ≥1000 random targets of the same length return no hit at the reporting threshold. Record both in the registry row. A negative without a passing control is "not tested".

9. **Era plausibility.** Each hypothesis names the software, platform, and date that would have produced it. Implausible-but-cheap tests are allowed, tagged `implausible`, and still counted in `search_bits`.

10. **Pre-registration where labels exist.** For Phase 1 and any labelled comparison, commit the feature list and rule families before joining labels to features. Anything formed after looking at the target or labels is tagged `exploratory`, counts in `search_bits`, and is capped at Tier C until a confirmation test fixed in advance passes on control constants.

11. **Reproducibility.** Every reported number is regenerated by one documented command inside the pinned container. Jobs are deterministic, checkpointed, resumable. Hot loops are compiled code with a Python reference that agrees on test vectors.

12. **Prior-art sweep.** At the start of each phase and before each gate report, search for new public results on that phase's targets and record what was found.

13. **Weakness or trapdoor: stop.** Any result suggesting an exploitable weakness, a recoverable protective secret, or deliberate manipulation is out of scope for autonomous follow-up. Stop, write a private note to the user, wait. This is strongest for the Dual_EC phase (a recovered scalar is a live key-recovery): do not commit it, do not publish, name coordinated-disclosure contacts for the user.

14. **Time boxes.** Each phase has a budget (`PROPOSAL.md` §6). At 100% of budget, write the gate report with what exists.
